# Admin browser user lookup, version 1

Only a live Admin Database stream may advertise `user_lookup: {version:1, nonce:<UUID>}`. Bearer impersonation never advertises it. Advertising does not access the signer. Sage registers `read_users` and `search_users` only after validating the Admin cookie, Database Tool Set, stream and capability. Without them, SQL/ID answers remain supported.

## Tools

Identity and ranking lookups default to selecting only `name`; IDs are automatic. Email and profile values are selected only when specifically requested by the user or necessary for the stated predicate. Native schemas, descriptions and DB guidance communicate this without query routing or overrides of the model's explicit selection.

- `read_users`: `{user_ids:[positive safe integer, ...], select:[selector, ...], cursor?:string}`. 1–20 distinct IDs; 1–3 distinct selectors (default name). Missing IDs produce explicit missing_user rows. Search matches deleted between the live scan and output projection also return missing_user with their ID. Continuation repeats the original arguments with the returned cursor.
- `search_users`: `{where:[{field:selector, operator:equals|contains|gt|gte|lt|lte, value:string|number|boolean}], select:[selector,...], metadata?:{approved?:boolean,user_type_id?:positive integer,pubkey_present?:boolean}, limit?:1..5, cursor?:string}`. 1–3 conjunctive predicates, 1–3 result selectors, default limit 5. Selectors: name, email, field:<positive definition ID>. String equals/contains is case-insensitive; numeric comparisons require number field metadata and finite numeric input; checkbox equals requires boolean. Missing values do not match; unreadable predicates are unknown, counted separately. Predicate strings are limited to 1000 Unicode scalar values (code points), independent of UTF-8 bytes or UTF-16 units; unpaired surrogates are rejected. The native schema declares maxLength:1000, and Sage rejects unsupported arguments before emitting SSE. Predicates always evaluate full values before output excerpts.

## Projected read

POST `/admin/user-lookup/projection`: `{user_ids?:[...], after_id?:0, through_id?:integer, limit?:1..100, select:[1..6 selectors], where?:[predicates], metadata?:{...}}`. Exact IDs and pages are exclusive. Page traversal uses `id > after_id AND id <= through_id ORDER BY id`; first request captures current max ID. Response `{users:[{id,values:{selector:null|{value:string}|{ciphertext,ephemeral_pubkey}}}], fields:[{selector,type}], through_id, next_after_id, eligible}`. Missing exact IDs are absent. `eligible` is the current count within the ID window/filter. Only requested columns/definition IDs are read; metadata and values are batched. Field labels never address values. Admin auth and existing CSRF middleware apply. No decrypt operation runs on the server.

GET `/admin/user-lookup/session` returns `{pubkey,session_fingerprint}` for the current valid Admin cookie (SHA-256 of the exact authenticated token). Responses are no-store. This supports browser credential checks without exposing the token. Sage uses the same fingerprint.

## Dedicated bridge

SSE `user_lookup_request` (never trace_delta): `{version:1, conversation_id, turn_id, call_id, nonce, session_fingerprint, admin_pubkey, expires_at:<Unix milliseconds>, operation:read_users|search_users, args:<validated tool arguments>}`. No callback URL. Browser verifies the event, session and active NIP-07 pubkey before work and around async operations; its serialized decrypt queue rechecks cancellation and the signer key inside the queue, before and after the signer await. Credential checks are forced before each projected batch and before result delivery; during a lookup a one-second background monitor checks the session even while a permission dialog is pending. Between these boundaries the maximum credential freshness interval is one second plus the in-flight validation latency, bounded by the call deadline; local logout/storage/abort events cancel immediately. Per-field key checks do not make HTTP requests unless this freshness interval expired.

POST `/llm/chat/user-lookup-result`: `{conversation_id,turn_id,call_id,nonce,result}`. Gateway routes exactly to Sage. Sage limits bytes before parsing (4096), validates current Admin auth and CSRF, exact session fingerprint, correlation, expiry, requested IDs/fields, schema, bounds and budget. Pending waits expire after 120 seconds without automatic retry. Identical repeats are idempotent only until expiry/stream disposal; conflicting, foreign, unsolicited and late submissions fail. Drop guards remove pending waits on cancellation and all turn records on stream drop.

## Result budget and paging

Success: `{status:"ok",users:[{id,status:"ok"|"missing_user",fields:{selector:{status:"ok",value:string,excerpt:boolean}|{status:"missing"|"unreadable"}}}],coverage:{scanned,eligible,unreadable,complete},matched_so_far,matched_count:number|null,next_scan:string|null,next_page:string|null,consistency:"live_id_window"}`. Read counts describe requested IDs. Search exact matched_count is supplied only on complete, fully readable coverage. Complete describes scan coverage; next_page may still hold undelivered matches. Each call scans at most 1000 eligible rows in batches of 20, and may stop earlier to deliver matches. A sparse batch followed by a dense batch may buffer up to 24 matching IDs; each output projection selects only a bounded prefix (at most 20 IDs), and unprojected IDs remain buffered. `next_page` drains buffered match IDs without scanning; `next_scan` advances scanning after those IDs are drained. Both are opaque, one-use, turn-scoped browser tokens; stale/mismatched cursors fail explicitly. The same cursor field accepts either kind. Changing/deleting rows during a scan is possible; no transactional snapshot or exact population claim is made.

Failure: `{status:"error",code:<fixed enum>}`. No raw exception/predicate/value is returned in errors. Every serialized result is <=1200 UTF-8 bytes before Sage's native wrapper (minimum shared native slot is 1500 characters). Whole rows are paged. Individual field values are explicitly excerpted to <=80 JSON-encoded UTF-8 bytes so even a three-field row fits. No generic JSON clipping. IDs always accompany names.

Browser stores at most 16 cursors and 128 cached values/128KiB per turn; cache keys contain Admin pubkey, user ID, selector and ciphertext fingerprint. Fresh projections invalidate changed values. No persistent plaintext store or whole-roster index. Stream EOF without completion, caller abort/unmount, logout/session/key change and expiry abort work and clear state. In-flight signer calls cannot be canceled; their late answers are discarded and queued calls check before prompting. A stream accepted by the server is non-replayable even before assistant text. Both Admin surfaces use the shared transport.

Raw lookup arguments/results never enter trace hooks, tool summaries, audit payloads or persisted tool memory. Only redacted progress/status enters traces; `tools_used` includes a dedicated admin-user-lookup summary with the operation name and completion/unavailable status. Unavailable lookups are guarded, and their native execution outcome is rejected; summaries and Activity IDs remain distinct from SQL. The normal final answer/history remains persisted. Profile text is untrusted data, not instructions.
