## Consistent encrypted backup

The previous `scripts/backup.sh` and `scripts/restore.sh` targeted legacy Neo4j and were unsuitable for this migration. They now delegate to the current Python commands; obsolete positional arguments fail instead of producing an incomplete legacy backup. Use `scripts/operations/backup.py` on the Linux Docker host with Python 3 and restic 0.19.1 or newer installed. The workflow uses restic's documented [encrypted snapshot backup](https://restic.readthedocs.io/en/stable/040_backup.html) and [verified isolated restore](https://restic.readthedocs.io/en/stable/050_restore.html) operations.

The tool discovers every bind mount and named volume in the selected Compose project, plus its Compose files and explicitly supplied private configuration. It includes SQLite, Postgres, Qdrant, uploads, Sage workspace, embedding cache, and mounted logs/configuration. It saves custom application images and complete container metadata for recovery. Runtime metadata contains credentials and must remain inside the encrypted repository or a private restored directory.

The backup first exports immutable custom images while services are online. It then enables an API maintenance response, drains application writers before stopping storage, and captures all persistent sources into an encrypted local restic checkpoint. The frontend remains running; writable frontend mounts are rejected before any service is stopped. Recovery starts supporting services and waits for health, then backend/Sage, then the gateway. Only after recovery succeeds does it remove maintenance and copy the checkpoint to the off-host repository. Network upload and retention therefore do not extend the service pause. The result includes measured `pause_seconds`; this is a brief maintenance window, not zero-downtime backup.

The local checkpoint uses the same password file and chunker parameters as the remote repository, preserving deduplication and the existing absolute-path restore format. `/var/lib/enclave-backup` must remain mode 0700. Before capture, the tool prunes its tool-owned local repository to two previous checkpoints, then estimates space for all sources, two copies of exported images and 1 GiB headroom. A new capture can temporarily make three. Failed uploads leave an encrypted local candidate for investigation; only complete off-host copies receive `enclave:PROJECT`. The local checkpoint is not a substitute for off-host recovery or separate password custody.

Capture failures and SIGTERM/SIGINT still recover all originally running paused services; previously stopped services stay stopped. Cancellation is recorded while an external command is in flight and honored only after that command finishes, preventing an abandoned Docker shutdown or a stale restic lock. Child commands run in separate sessions so terminal Ctrl-C reaches the coordinator. Signals during recovery are deferred until every tier has been attempted, and interruption skips upload/retention. Cancellation can therefore wait for the active capture or network command to finish. A recovery failure leaves `/run/enclave-backup/maintenance` in place and reports failure through the existing notification service. Inspect all ten services, verify gateway health, and remove that marker only after recovery is healthy. A pre-existing marker blocks another backup. `RuntimeDirectoryPreserve=yes` keeps it after a failed unit; a host reboot clears `/run`. A forced kill or host crash can bypass cleanup, so inspect service health and the previous encrypted runtime manifest before resuming traffic.

Create an organization-owned off-host repository, save the restic password separately, and initialize it once. Set the values from `scripts/operations/backup.env.example` in root-owned `/etc/enclave-backup/production-backup.env` with mode 0600, and save its password in `/etc/enclave-backup/restic-password.key` with mode 0600. The developer saves recovery keys in Proton Pass and manually hands them to the organization over Signal. Losing the repository password prevents restoration even if the bucket is available.

Custom image export needs temporary disk capacity; verify free space first.
